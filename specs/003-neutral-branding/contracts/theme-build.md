# Contract: neutral theme build output

Interface: what `branding.render(root, view)` writes for a guide with `theme: neutral`, what `check.py` and `print-pdf.mjs` rely on, and what the scaffold script vendors.

## Vendored assets

`guide/adapters/antora/branding/fonts/` in the plugin, `tools/guide/branding/fonts/` in a guide project (copied by `scaffold-project.sh`, full and `--toolkit-only`):

```text
fonts/
├── fonts.yaml                       # manifest (data-model.md)
├── OFL.txt
├── RedHatDisplay-VF.woff2
├── RedHatDisplay-Italic-VF.woff2
├── RedHatText-VF.woff2
├── RedHatText-Italic-VF.woff2
├── RedHatMono-VF.woff2
└── RedHatMono-Italic-VF.woff2
```

`update-fonts.py` lives next to the manifest in the plugin and is excluded from the vendored copy.

## Overlay files

With `theme: neutral`, the merged overlay `build/branding/<view>/ui/` contains, in addition to the spec 002 files:

- `font/` with the six fonts and `OFL.txt`, byte-identical to the vendored copies;
- `css/theme-neutral.css`, beginning with the line `/* Generated by tools/guide/branding.py from the guide.yaml branding theme; do not edit. */`, then one `@font-face` block per font, then the rule `.navbar { box-shadow: inset 0 -3px 0 #e00; }`, and nothing else;
- `partials/head-meta.hbs` with the link order: favicon link, `css/branding.css` (when `color`), `css/theme-neutral.css`, `css/extra.css` (when present);
- `partials/head-styles.hbs` containing only `    <link rel="stylesheet" href="{{{uiRootPath}}}/css/site.css">` (the stock partial minus its Google Fonts links), so the page makes no third-party font request.

`@font-face` block shape (one per font, in manifest order):

```css
@font-face { font-family: "Red Hat Text"; src: url("../font/RedHatText-VF.woff2") format("woff2"); font-weight: 300 700; font-style: normal; font-display: swap; }
```

With `theme: stock` or no `theme`, none of these files is generated and `head-meta.hbs` is byte-identical to its spec 002 output.

## Logo

`img/logo-guide.svg` for an outlined logo:

- contains no `<text>` element and at least one `<path>` per non-space character;
- for `wordmark`: `viewBox="0 0 <W> 178.739"`, one `<g transform="translate(0 118.07)" fill="#fff">` holding the glyph paths (capitals centered vertically, research R8), and a comment naming Red Hat Display, release 5.0.0, and the OFL;
- for `logo_text` with `neutral`: the template's hat, wordmark, divider, and MPL-2.0 comment unchanged, and the `<text>` element replaced by `<g transform="translate(308 149)" fill="#fff">` with the glyph paths; `viewBox` width `max(780, ceil(308 + advance + 24))`.

Rendering the same text with the same font and toolkit version yields the same bytes.

## `branding.json`

```json
{
  "logo": "/abs/build/branding/shareable/ui/img/logo-guide.svg",
  "alt": "OpenClaw on OpenShift",
  "footer": "none",
  "theme": "neutral",
  "fonts": "/abs/build/branding/shareable/ui/font",
  "font_faces": [{"family": "Red Hat Display", "file": "RedHatDisplay-VF.woff2", "weight": [300, 900], "style": "normal"}],
  "generated": ["..."],
  "shadowed": []
}
```

`print-pdf.mjs` reads `theme`, `fonts`, and `font_faces` (the example shows one of the six entries). A neutral guide whose `fonts` directory is missing fails with `branding output missing for the <view> view; run make check`, like a missing logo.

## PDF typography (neutral only)

| Element | Stock | Neutral |
|---|---|---|
| `body` and every element in it (`body *`, which reaches Asciidoctor's serif italic block titles) | Noto Serif, DejaVu Serif, Georgia, serif | Red Hat Text |
| `h1` to `h6`, `.guide-title-page`, `.guide-toc` | inherited or Helvetica | Red Hat Display; headings at weight 500 (Asciidoctor's 300 looks too thin in Red Hat Display) |
| `pre`, `code` | browser monospace | Red Hat Mono |
| `.guide-brand-band` | `#151515` band | same, plus `border-bottom: 3px solid #e00` |

Fonts load from `file:` URLs into the `fonts` directory. The existing block on remote fonts stays. The printer loads every face with `document.fonts.load()` before printing (faces otherwise load only once layout needs them, after `document.fonts.ready` may already have resolved) and fails with `vendored fonts failed to load: <faces>` when one does not load. Pseudo-elements (the admonition labels) and the page-number footer keep Helvetica. Chromium embeds the variable fonts as unnamed Type3 fonts, so a PDF check cannot find them by name; it checks for Type3 fonts and the absence of serif fallbacks instead.

## make check (neutral guides)

For each checked view (shareable; internal while enabled):

- every built page outside `_exports/` must link `css/theme-neutral.css` (`[branding] page does not load the neutral theme`) and no Google Fonts host (`[branding] page still loads Google Fonts`);
- `build/<view>/_/font/` must contain each of the six fonts and `OFL.txt` (`[branding] neutral theme font missing: <file>`).

An author file at `ui/supplemental/css/theme-neutral.css` satisfies the link check (the author owns it then).
